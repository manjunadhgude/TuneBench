## Limitations that matter to interpretation

- This is a deliberately small pipeline check, not a representative quality benchmark or an untouched final test.
- There are no exact prompt duplicates, but several near duplicates vary only an ID/product/amount. Examples 1 and 4 use the same wording; eligibility and missing-field families are strongly templated; policy examples 16 and 17 differ only by reference. Do not treat these as independent reasoning patterns.
- Eligibility/refund examples cover only `damaged_item`, not the other allowed reasons. There are no ambiguous-target, conflicting-reference, cross-turn, or hard reasoning samples in this smoke set. Poor/full-suite generalization cannot be inferred from a successful smoke run.
- Missing-field prompts announce the omission directly, and no-tool prompts often explicitly forbid the distracting tool action. This makes the smoke set easier than realistic user traffic.
- Example 8 has a harmless grammar issue: “the headphones was damaged.” Its intent and gold arguments remain clear; correcting grammar is optional and should not silently change the reviewed dataset before recording model results.
- No exchange-rate/currency policy, order-ID regex, refund eligibility outcome, account ownership, amount ceiling, or real payment behavior is invented by the gold labels. Tool selection/proposal formation is what these records test.
- A no-tool outcome specifies that none of the available tools should be called; it does not assert that an answer about policy/contact/product facts is factually known.
